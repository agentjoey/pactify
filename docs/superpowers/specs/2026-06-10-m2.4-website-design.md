# M2.4 — pactify.dev Website v1 — Design

- **Milestone:** Phase 2 / M2.4 (Sprint 003)
- **Date:** 2026-06-10
- **Status:** approved (brainstorm) → ready for implementation plan
- **Depends on:** M2.2 complete (v0.3.0 released; install.sh exists at repo root; `docs/specs/pact-protocol.md` + `docs/agent-onboarding.md` are the canonical docs)

## Goal

Ship pactify.dev v1: a terminal-authentic landing page, the protocol spec and agent
onboarding rendered as site pages, and `https://pactify.dev/install.sh` serving the real
installer — the canonical entry point the CLI, plugin hook, and README already point at.

### Decisions locked in brainstorm

1. **Visual direction: terminal-authentic** (Charm/Warp/Fly lineage) — monospace, dark,
   line-by-line typing, blinking cursor. "The product is the truth": the hero demos the
   actual protocol run. Chosen over Linear-dark / Stripe-gradient / Geist-typographic
   (user explored all four on the visual board).
2. **Pact motifs: 双线合一 (converging lines) + 入座 (taking a seat).** Two agent paths
   merging into one line = collaboration/merge (hero background); dashed empty seats
   lighting up solid = any agent can join (agents section). Both map to real protocol
   concepts, not decoration. (Signature/seal/clause/ledger motifs considered; clause
   typography survives as the §1/§2 rules cards — content, not a motion system.)
3. **Hosting: Vercel.** Static output only, zero Vercel-exclusive features — Phase 6
   (China GTM) migration stays trivial. User accepted the China constraint explicitly.
4. **Stack: Astro** (static-first, markdown-native). Future cloud product (accounts,
   auth, payments — Pact-Team, Phase 4–5) lives at `app.pactify.dev` as a **separate
   Next.js app** later; the marketing site stays light. (www/app split chosen over
   one-Next.js-codebase after weighing both.)
5. **Location: monorepo `site/` directory** — protocol/onboarding pages read the
   canonical markdown from `../docs/` at build time (single source of truth, no copies);
   `install.sh` is copied from the repo root into the build (with a sync test).
6. **v1 scope: landing + /protocol + /onboarding + /install.sh.** English only.

## §1 Information architecture

```
site/                          Astro project (monorepo subdirectory)
pactify.dev/                   landing (single page)
pactify.dev/protocol           renders docs/specs/pact-protocol.md (full spec)
pactify.dev/onboarding         renders docs/agent-onboarding.md (per-agent manual reference)
pactify.dev/install.sh         the real installer (copied from repo root at build, text/x-sh)
```

## §2 Landing page content (mockup-approved)

Top to bottom — structure validated via the visual-companion mockup
(`.superpowers/brainstorm/*/content/landing-mockup.html`):

1. **Nav**: `pactify` wordmark · protocol · onboarding · GitHub link.
2. **Hero**: headline **"Agents, in agreement."** + subline ("pact is a git-native
   coordination protocol for AI agents — append-only log, enforced review, any agent can
   take a seat."). Background: the converging-lines SVG animation (two colored paths merge
   into one, looping). Centerpiece: a terminal window typing the real flow line by line —
   `curl … install.sh | sh` → `pactify 0.3.0 installed` → `pactify setup` → seats → worker
   joined → `T1 accepted · F1 shipped` + blinking cursor. CTA: the one-line curl command
   in a copyable code chip.
3. **The two rules**: §1 / §2 contract-clause cards (worker cannot self-accept; no merge
   until all tasks accepted) under the label "The pact — two rules, enforced".
4. **Quickstart** ("Five minutes to a working pact"): 4 steps — install → `pactify setup`
   → `pactify doctor` → launch your agent, you just say "start".
5. **Seats section** ("Any agent can take a seat"): dashed seat cards lighting up —
   Claude Code (one-click plugin) · opencode (auto-wired) · Gemini CLI (auto-wired) ·
   Codex (config snippet) · Desktop apps (`--project`).
6. **Footer**: MIT · protocol v1 frozen · github / protocol / onboarding links.

## §3 Visual & motion system

- **Palette**: dark base `#0c1117` family; borders `#1d242e/#2d3640`; text `#cdd9e5` /
  dim `#7d8590`; accents — green `#6ee7a0` (actions), blue `#8ab4ff` (confirmations),
  yellow `#ffd479` (seats/identity).
- **Type**: system monospace stack (`ui-monospace, SFMono-Regular, Menlo, monospace`) —
  no webfonts. Sans only for the hero headline if needed; default is mono everywhere.
- **Motion (CSS/SVG only, no JS animation libraries)**: exactly four primitives —
  terminal line-by-line reveal, blinking cursor, converging-lines stroke draw,
  seat dashed→solid transition. All wrapped in `@media (prefers-reduced-motion: no-preference)`;
  reduced-motion users see the final static frame.
- **No client framework**: zero React/islands; the few animations are pure CSS keyframes
  (the mockup proved sufficiency). Plain `<script>` only if copy-to-clipboard on the CTA
  chip is included (progressive enhancement, optional).

## §4 Technical architecture & data flow (single source of truth)

- **Astro (current major — 6.x at design time)**, `output: 'static'`. No integrations
  beyond what markdown rendering needs.
- **/protocol and /onboarding** import the canonical files at build time from the repo
  (`../docs/specs/pact-protocol.md`, `../docs/agent-onboarding.md`) — not copies. Docs
  changes flow into the next site build automatically. Rendered inside a shared
  terminal-styled docs layout (mono, dark, same tokens).
- **install.sh**: a build step (`prebuild` script) copies `../install.sh` into `public/`
  so it ships at `/install.sh`. A test asserts byte-equality between `site/public/install.sh`
  presence in dist and the repo root file (drift guard). Vercel serves correct
  `Content-Type` for `.sh` as text — verify with curl post-deploy; if needed, a
  `vercel.json`-free fallback is acceptable since `curl | sh` only needs the bytes.
- **Meta**: title/description/OG tags per page; favicon = terminal block-cursor mark
  (simple SVG). No analytics.

## §5 Deployment

- Vercel project: **Root Directory = `site/`**, framework preset Astro, static output.
  Production branch `main`. Build skipped unless `site/`, `docs/specs/pact-protocol.md`,
  `docs/agent-onboarding.md`, or `install.sh` changed (Vercel "ignored build step" git diff check).
- **DNS**: pactify.dev currently has no records. Maintainer adds the records at the
  registrar per Vercel's instructions (A/ALIAS + CNAME for www → documented in the plan;
  exact values come from Vercel's domain panel).
- **CI**: add a `site` job to `.github/workflows/ci.yml` — `npm ci && npm run build` in
  `site/` + the dist assertions from §6. It runs alongside the Go job; branch protection
  continues to require only the `test` check (the site job is informative first; can be
  promoted to required later).

## §6 Testing

- `astro build` succeeds (CI).
- Dist assertions (small node/shell script in CI): `dist/install.sh` exists and is
  byte-identical to the repo root `install.sh`; `dist/protocol/index.html` contains the
  spec's title text; `dist/index.html` contains the curl one-liner and the §1/§2 rule text.
- No browser/E2E tests (YAGNI for a static site).

## §7 Out of scope (v1)

Chinese/i18n (Phase 6) · `app.pactify.dev` cloud product (Phase 4–5, separate Next.js) ·
blog/changelog · analytics · custom webfonts · dark/light toggle (dark only) ·
search · versioned docs.
