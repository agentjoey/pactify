## 0. 目标

协议 v1 已冻结（bash 参考实现 73/73 测试，GitHub 上线）。M1.2 用 Go 实现同一契约（`pact-protocol.md §7` 的动词），产出单静态二进制 `pactify`，与 bash `pact.sh` **可互换**（"一套契约两种皮"）。bash 保留为参考/互操作 oracle/无 Go 环境 fallback。**不含** serve/MCP/dashboard（M1.3）。

## 1. 范围 + 模块/包结构

**Module**：`github.com/agentjoey/pactify`

```
go.mod
cmd/pactify/
  main.go                # cobra root，wire 各 verb
  cmd_init.go … cmd_help.go   # 薄命令层：解析 flag → 调 internal/pact
internal/
  event/                 # 事件信封 + log.jsonl 读写 + event_id/ts
    event.go             # Event struct, EventType 常量, role 派生 map
    log.go               # Append(原子) / ReadAll(忽略未知字段)
    id.go                # event_id (crypto/rand 16B hex), nowUTC()
  projection/            # 事件折叠 → State + 渲染 STATE.yml
    project.go           # Project([]Event) State; State/Feature/Task 结构
    render.go            # Render(State) string —— 字节对齐 bash 格式
  pact/                  # 协议引擎（verb 核心逻辑）
    engine.go            # Init/Join/Assign/Checkpoint/Accept/Changes/Merge/Status/Log/Validate
    rules.go             # 两条铁律 + 状态前置 + 版本门禁 + event_id 必查
    seat.go              # 座位解析/roster/受管区块入口文件烘焙
  gitx/                  # git 操作（exec git，副作用隔离）
    gitx.go              # CurrentBranch/CheckoutOrCreate/Commit/MergeNoFF/HasChanges
  paths/                 # PACT_DIR/LOG/STATE/TASKS 解析 + PACT_AGENT_ID + PROTOCOL_VERSION 常量
```

**分解理由**：`event`=wire 格式；`projection`=读模型（纯函数，无副作用，易测）；`pact`=引擎（校验+追加+渲染+git 编排）；`gitx`=git 副作用隔离（独立测/可 mock）；`cmd`=薄壳。每包单一职责。

依赖姿态：**唯一 build-time 第三方依赖 = `spf13/cobra`**。STATE.yml 手写渲染（§3，不引 yaml 库）；log.jsonl 用 stdlib `encoding/json`；event_id 用 stdlib `crypto/rand`（不引 uuid）。无处解析 YAML（STATE 只写不读，log 是 JSON）。**runtime 零依赖**（单静态二进制）。

## 2. 核心类型 + 引擎流程

**事件信封**（匹配 `schemas/event.schema.json`）：
```go
type Event struct {
    EventID   string         `json:"event_id"`
    TS        string         `json:"ts"`        // UTC ISO-8601
    AgentID   string         `json:"agent_id"`
    Role      string         `json:"role"`      // 由 verb 派生
    EventType string         `json:"event_type"`
    TaskID    string         `json:"task_id"`   // "" 当不适用
    Feature   string         `json:"feature"`   // "" 当不适用
    Payload   map[string]any `json:"payload"`
}
```
- `log.Append(dir, ev)`：序列化一行 + `O_APPEND` 原子写整行；`event_id` = `crypto/rand` 16B hex。
- `log.ReadAll(dir) ([]Event, error)`：逐行解析；忽略未知顶层字段（struct 丢弃多余键）与未知 `event_type`（投影跳过）。

**投影**（纯函数，镜像 `_pact_project_json`）：
```go
type State struct {
    Project           string
    WorkingTreeHolder *string
    Agents            []Seat       // 来自 init 事件的 seats
    Features          []Feature
}
type Feature struct { ID, Branch, Status string; Tasks []Task }
type Task struct { ID, Owner, Status, Reviewer, Spec string; Evidence *string }
func Project(evs []Event) State
```
fold 规则同 bash：`assign` 建 task(assigned)、`join` 把该座位 assigned→in_progress、`checkpoint`→awaiting_review+evidence、`accept`→accepted、`changes_requested`→changes_requested、`merge`→feature shipped、未知 event_type 跳过。`agents` 来自最后一个 init 事件的 `seats`。

**引擎每 verb 统一流程**（与 bash 一致）：
```
1. requireAgentID()                         # 缺 PACT_AGENT_ID → fail-closed (非0退出)
2. evs := log.ReadAll(); st := Project(evs)  # 读 + 投影
3. rules 校验前置（按 verb）：
     assign: owner≠reviewer; task_id 全局唯一
     checkpoint: caller==owner; evidence 非空
     accept/changes: caller==reviewer; task 当前 awaiting_review
     merge: feature 存在且有 task; 全 task accepted
4. log.Append(event)                         # role 由 verb 派生
5. projection.Render → 写 STATE.yml（原子 tmp+rename）
6. gitx（按需）：join→CheckoutOrCreate(branch); checkpoint→提交全部改动; 
                  merge→提交 pending + Checkout(base_branch) + MergeNoFF(branch)
```

**rules.go** 集中两条铁律 + 状态前置 + 版本门禁（init.protocol_version 高于支持 major → 拒）+ event_id 必查；`Validate()` 复用同组检查（对应 bash validate 7 项：drift / roster / slug / rule1 / task 唯一 / 版本 / event_id）。

**role 派生 map**（不信任入参）：`init/assign/merge→orchestrator`、`join/checkpoint→worker`、`accept/changes→reviewer`。

## 3. STATE 渲染 + 跨工具互操作（决策：A 字节对齐）

`projection.Render(State)` **手写渲染，字节对齐 bash `_pact_render_state_to` 的格式**：
```yaml
project: <name>
working_tree_holder: null
agents:
  - { id: <id>, roles: [<r1>, <r2>] }
features:
  - id: <F>
    branch: <b>
    status: <s>
    tasks:
      - id: <T>
        owner: <o>
        status: <st>
        reviewer: <rv>
        spec: <path>
        evidence: <single-line; 换行/tab 折叠为空格 | null>
```
**理由**：让 STATE.yml 跨工具字节稳定 —— bash 渲染的 STATE 与 Go 渲染的 STATE 完全一致，**任一工具的 `validate` 漂移检查在另一工具产出的 STATE 上也直接通过**，无需 `log --replay` 重渲。这把"两皮"承诺贯彻到 STATE 层（不止 log 层）。spec §9 虽列 STATE 格式为实现自定义，但自愿字节对齐是更强互操作、不违背 spec。

→ 不引 yaml.v3 做 render（手写 = 完全控制格式 + 少一个依赖）。evidence 折叠规则同 bash（`gsub("\n";" ")`、`gsub("\t";" ")`）。

## 4. cobra / 构建 / 分发

- `cmd/pactify` cobra root；每 verb 一个 `cobra.Command`（薄：解析 flag → 调 `internal/pact`）；自动 `--help`/usage。
- 动词 + 必填参数同 `pact-protocol.md §7`：`init/join/assign/checkpoint/accept/changes/merge/status/log/validate/help`。实现可加 `--flag`（非破坏）。
- 退出码：成功 0；校验/铁律/fail-closed 失败 非0（与 bash 一致，agent 可判）。
- 构建：`go build -o pactify ./cmd/pactify`（单静态二进制）；`go install` 可用。
- `pactify init` 烘焙的入口文件引导 `pactify <verb>`；bash `pact_init` 烘 `pact.sh`。两套各自自洽，log 层互通。

## 5. 测试（B：原生 + schema + 互操作）

1. **go test 原生套件**：
   - `internal/projection`：喂事件序列断言 State（含未知 event_type 跳过、各状态转换）。
   - `internal/pact`：每 verb + 两条铁律（自接受拦截、未全 accepted 拒 merge）+ 状态机 + 版本门禁 + fail-closed，镜像 bats 场景。
   - `internal/gitx`：临时 git repo 跑真 git（CheckoutOrCreate/Commit/MergeNoFF）。
2. **schema 一致性**：Go 跑完整 6 段流程产 log → 每条事件用 `schemas/event.schema.json` 校验（测试中 shell 调 python jsonschema，复用现成校验器）。
3. **跨实现互操作**（B 核心，新 `tests/interop.bats`，bash + 新建 Go 二进制并用）：
   - **bash → Go**：`pact_init`+`pact_assign`（bash）→ `pactify join/checkpoint/accept/merge`（Go）→ feature shipped；断言 **bash `pact_validate` 与 Go `pactify validate` 都过**，STATE.yml 字节一致。
   - **Go → bash**：`pactify init`（Go）→ bash 读/续 → 一致。
   - 前置：测试 setup 先 `go build -o <tmp>/pactify ./cmd/pactify`。

**验收**：所有 go test 绿；现有 73 bats 保持绿；interop.bats 绿；Go 产 log 过 event.schema.json。
