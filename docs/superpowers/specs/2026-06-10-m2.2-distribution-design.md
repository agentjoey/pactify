# M2.2 — Distribution + Guided Onboarding + Claude One-Click — Design

- **Milestone:** Phase 2 / M2.2 (Sprint 003)
- **Date:** 2026-06-10
- **Status:** approved (brainstorm) → ready for implementation plan
- **Depends on:** M2.1 complete (agent registry, `pactify agent add`/`init` kinds, `pactify mcp --project`)

## Goal

Make pactify trivially installable and adoptable. Get the `pactify` binary onto each
agent's PATH (so the M2.1-wired bare `pactify` MCP commands resolve), give every user a
one-command guided setup, and ship a one-click Claude plugin as the marketplace template.

### Decisions locked in brainstorm

1. **F1 resolution:** agent configs keep the bare `pactify` command; distribution puts
   it on PATH. Project-scoped configs are committed and shared, so an absolute binary
   path would be machine-specific garbage — bare command + PATH is correct. **No agent
   package code changes.**
2. **Install channels (this milestone):** `go install`, `curl … | sh`, and GitHub
   Releases (multi-platform binaries). brew tap deferred.
3. **Release tooling:** GoReleaser.
4. **CI + branch protection:** GitHub Actions runs the full suite on push + PR; `main`
   requires CI green + PR, with "allow administrators to bypass" enabled.
5. **Claude one-click:** a `pact` plugin (skill + bundled MCP server) + a same-repo
   marketplace; a SessionStart hook detects a missing `pactify` and **prints** the
   install command (never installs silently).
6. **Guided onboarding lives in the CLI:** `pactify setup` (interactive) + `pactify
   doctor` (diagnostic) are the canonical flow; install.sh, the plugin hook, and the
   README all point to it. This works for non-Claude users too (the CLI is the one
   surface everyone shares).
7. **Platforms:** darwin + linux × amd64 + arm64. Windows deferred.

## Three pillars

- **A. CLI binary distribution** — version injection, GoReleaser, install.sh, go install, CI, release workflow, branch protection.
- **B. Guided onboarding** — `pactify doctor`, `pactify setup`; every channel points here.
- **C. Claude one-click plugin** — `plugins/pact/` + `.claude-plugin/marketplace.json`.

Pillars are sequenced A → B → C: B's `doctor` checks A's install; C's hook points at B.

## Pillar A — CLI binary distribution

### A1 — version injection
`cmd/pactify/main.go` (or a tiny `internal/buildinfo`) carries `var version = "dev"`
(plus `commit`, `date`). Add a `pactify version` subcommand and a `--version` flag that
print `pactify <version> (<commit>, <date>)`. Release builds inject real values via
ldflags `-X main.version=<tag> -X main.commit=<sha> -X main.date=<iso>`; a plain
`go build`/`go install` leaves `dev`. Unit-tested via the command's output with the
default values.

### A2 — `.goreleaser.yaml`
GoReleaser config at repo root:
- builds: `goos: [darwin, linux]`, `goarch: [amd64, arm64]`, `main: ./cmd/pactify`,
  `binary: pactify`, `CGO_ENABLED=0`, ldflags injecting version/commit/date.
- archives: `tar.gz`, name `pactify_{{.Os}}_{{.Arch}}`.
- checksum: `checksums.txt` (sha256).
- release: GitHub Release, on tags matching `v*`.
- (brew formula block omitted this milestone — deferred.)
Validated locally with `goreleaser check` and `goreleaser release --snapshot --clean`
(builds all targets without publishing).

### A3 — `install.sh` (repo root)
POSIX `sh` script:
1. Detect OS (`uname -s` → darwin/linux) and arch (`uname -m` → amd64/arm64; map
   `x86_64`→amd64, `aarch64`/`arm64`→arm64). Unsupported → clear error.
2. Resolve the latest release tag from the GitHub API (or accept `PACTIFY_VERSION`).
3. Download `pactify_<os>_<arch>.tar.gz` + `checksums.txt` from the release; verify
   sha256; abort on mismatch.
4. Extract and install `pactify` to the first writable of `/usr/local/bin` then
   `~/.local/bin`; `chmod +x`. If the chosen dir is not on PATH, print how to add it.
5. Print: `✅ pactify <version> installed. Run \`pactify setup\` in your repo to get started.`
Idempotent (re-running re-installs). `shellcheck`-clean; a CI job runs it against the
GoReleaser snapshot artifacts to prove end-to-end install works.
User-facing command (until pactify.dev exists, M2.4):
`curl -fsSL https://raw.githubusercontent.com/agentjoey/pactify/main/install.sh | sh`

### A4 — `go install`
Documented: `go install github.com/agentjoey/pactify/cmd/pactify@latest`. Works because
version handling tolerates missing ldflags (`dev`). README + `pactify version` note it.

### A5 — CI `.github/workflows/ci.yml`
On `push` and `pull_request`: set up Go 1.26 + Node; run `go vet ./...`,
`go test ./...`, `go build ./...`, `bats tests/`, and `( cd web && npm ci && npm test )`.
This is the gate referenced by branch protection. (Bats + perl available on the GitHub
ubuntu runner; install `bats` via the runner's package manager or the bats-core action.)

### A6 — release `.github/workflows/release.yml`
On tag push matching `v*`: checkout, set up Go, run `goreleaser release --clean` with
`GITHUB_TOKEN`. Produces the multi-platform archives + checksums + GitHub Release.

### A7 — branch protection
`main` protected: require the CI status check to pass + require a PR before merging;
enable "allow administrators to bypass" (so the maintainer can still direct-push
trivial docs/chore, matching CONTRIBUTING). Applied via
`gh api -X PUT repos/agentjoey/pactify/branches/main/protection …` and the exact call
documented in CONTRIBUTING.md.

## Pillar B — guided onboarding (the canonical flow)

### B1 — `pactify doctor` (non-interactive diagnostic)
Runs a checklist and prints `✓`/`✗` per item with a one-line remediation for each `✗`;
exits non-zero if any `✗`. Checks:
1. **PATH** — `os.Executable()`'s directory is on `$PATH` (so agents launching bare
   `pactify` will resolve it). `✗` → print how to add the dir / re-run install.sh.
2. **Repo context** — if cwd has `.pact/`: `validate` passes (reuse the engine's
   validation); else note "no .pact/ here — run `pactify setup` or `pactify init`".
3. **Seat** — `PACT_AGENT_ID` is set (warn if empty; needed for shell-fallback verbs).
4. **Agent wiring** — detect known agent config files in cwd (opencode.json, .mcp.json,
   .gemini/settings.json, AGENTS.md, …) and report which contain the `pact` server /
   briefing block.
5. **MCP** — `pactify mcp` can start: spawn it, complete an `initialize` handshake over
   stdio, confirm the tool list, then exit. `✗` → surfaces the stderr.
`doctor` is a thin orchestration over existing primitives (paths, validate, the agent
registry, the MCP server). Reused by `setup` and the Claude plugin hook.

### B2 — `pactify setup` (interactive, TTY)
Human-facing guided flow (stdin is a TTY):
1. Run the `doctor` PATH check; if `pactify` isn't on PATH, explain before continuing.
2. If cwd has no `.pact/`: prompt project name, seat id (`PACT_AGENT_ID`), and agent
   kind(s) from the registry; call the existing `init` / `agent.Wire` to scaffold +
   wire. If `.pact/` exists: offer to wire an additional agent (`agent add`).
3. Print the `export PACT_AGENT_ID=<seat>` line and how to persist it (do **not** edit
   the user's shell rc).
4. Run `doctor` to verify, then print next steps (assign/join, or "launch your agent").
**Non-TTY guard:** if stdin is not a TTY (piped, or an agent shell), `setup` prints a
short message pointing at the non-interactive primitives (`pactify init …` /
`pactify agent add …`) and exits 0 without prompting — agents never get blocked on a
prompt. `setup` adds no new wiring logic; it orchestrates `doctor` + `init` +
`agent.Wire` + prompts. Tested via: doctor's checks (table of repo states), setup's
non-TTY guard, and a TTY path driven by piped answers through the prompt reader.

### B3 — channel pointers (DRY: one flow, many entrypoints)
- `install.sh` final line → "run `pactify setup`".
- Claude plugin SessionStart hook (Pillar C) → missing pactify: install hint; present
  but `.pact/` absent or `doctor` fails: suggest `pactify setup` / `pactify doctor`.
- `README.md` quickstart → `curl … | sh` then `pactify setup`.
- pactify.dev quickstart → deferred to M2.4, same flow.

## Pillar C — Claude one-click plugin (marketplace template)

### C1 — plugin at `plugins/pact/`
- `.claude-plugin/plugin.json`: `{ name: "pact", description, version: "0.3.0",
  author, homepage, repository, license: "MIT" }`.
- `skills/pact/SKILL.md`: adapted from the existing `.claude/skills/pact/SKILL.md`
  (orchestrator/worker/reviewer roles, the two rules, MCP-first usage).
- `.mcp.json`: `{ "mcpServers": { "pact": { "command": "pactify", "args": ["mcp"] } } }`.
  **No `PACT_AGENT_ID` baked here** — the plugin is shared/installed read-only, but the
  seat is per-user/per-repo. The skill instructs the user to `export PACT_AGENT_ID=…`
  (or run `pactify setup`); the server reads it from the environment at launch.
- `hooks/hooks.json`: a `SessionStart` hook running a small POSIX script that
  `command -v pactify`; if missing, prints the `curl … | sh` install one-liner and a
  one-line "then run `pactify setup`" note (prints only — never installs). If present,
  silent.
- `README.md`: what the plugin adds + the binary prerequisite.

### C2 — `.claude-plugin/marketplace.json` (repo root)
`{ name: "pactify", owner: { name: "agentjoey" }, plugins: [ { name: "pact",
source: "./plugins/pact", description } ] }`. Same-repo plugin source (relative path,
resolved from the marketplace root). Users:
`/plugin marketplace add agentjoey/pactify` → `/plugin install pact@pactify`.
Validated with `claude plugin validate ./plugins/pact` (run in CI if the CLI is
available on the runner; otherwise documented as a local pre-release check).

### Plugin caveat (verified)
Claude Code copies an installed plugin to a cache dir, so the plugin cannot reference
files outside itself — confirming the binary must be on PATH (Pillar A) rather than
referenced from the repo.

## Testing

- **A:** `pactify version` unit test (default `dev` values); `goreleaser check` +
  `--snapshot` build of all 4 targets in CI; `install.sh` shellcheck + an end-to-end CI
  job installing from the snapshot artifacts; CI/release workflows are self-testing.
- **B:** `doctor` integration tests over a table of repo states (no `.pact/`, valid,
  drifted, wired/unwired, PATH on/off); `setup` non-TTY guard test + a TTY path driven
  by piped answers.
- **C:** `claude plugin validate` on `plugins/pact`; a test asserting `.mcp.json` and
  `marketplace.json` are well-formed JSON and the marketplace `source` path exists.
- **Baseline:** existing go test + bats + vitest stay green; the new CI workflow runs
  them on every push/PR.

## Scope / YAGNI

**In:** A1–A7, B1–B3, C1–C2.
**Out (later):** brew tap (M2.2.1 / M2.3); Windows; pactify.dev hosting of install.sh +
quickstart (M2.4); other marketplaces — Codex / opencode / Gemini one-click (M2.3);
auto-installing the binary from the plugin hook (rejected — print only).
