> 目标：把 Phase 0 的经验 schema 形式化、冻结为 **pact protocol v1**，让 Go CLI (M1.2)、MCP server / cloud relay 都建在稳定地基上。

## 0. 目标

Phase 0 跑出了一套能用的 `.pact/` 文件 + log.jsonl 事件 + 状态机 + 两条铁律（bash 参考实现，55/55 测试 + 真实跨 agent dogfood 通过）。M1.1 把它**冻结成 v1 契约**：任何实现（Go / 未来其他）行为一致、可互操作。这是"跨厂商中立"价值主张的地基。

## 1. 范围、交付物、契约边界

### 1.1 M1.1 交付物
1. `docs/specs/pact-protocol.md` — 规范正文（他人可独立实现 v1）
2. `schemas/*.json` — JSON Schema（机器可读规范工件；外部工具/校验用）
3. 把 bash 参考实现 `.pact/bin/pact.sh` 升到 v1（加 `event_id` + `init.protocol_version`）+ 测试，保持唯一一致参考、不漂移

### 1.2 冻结为 v1（契约，跨实现一致）
- log.jsonl 事件 schema（源 + 通讯总线）
- `.pact/` 文件布局：`PROJECT.md` 座位表、`tasks/<id>.md`、`log.jsonl`、`STATE.yml`
- 任务 / feature 状态机 + 两条铁律
- 座位身份语义（自声明、roster、职责分离、task_id 全局唯一）
- 命令动词名 + 必填参数语义（shell 接口）

### 1.3 明确 NOT 冻结（实现自定义，可演进）
- **git 分支/提交编排**：Phase 0 F1 的「join 切分支 / checkpoint 提交 / merge 回 base」是**推荐行为**，不是 wire 契约。worktree / 共享树 / 云端各有不同处理；为 Phase 1 worktree 隔离留空间。
- `STATE.yml` 的**精确渲染格式**：派生投影；结构有文档但 **log.jsonl 才是权威**，程序决策读 log 不读 STATE；实现可改渲染。
- `pactify serve` / dashboard / MCP 暴露细节（M1.3）。
- Go CLI 是否用 JSON Schema 校验库（M1.2 依赖姿态决定；v1 只要求行为符合 schema）。

## 2. 版本化规则

`protocol_version` = **单整数**，初始 `1`。写两处：
- `init` 事件的 `payload.protocol_version`（权威，随 log 走）
- `.pact/PROJECT.md` 头部标注（人可见）

兼容规则（冻进规范）：
1. **读者必须忽略未知字段和未知 `event_type`** —— 前向兼容基石。
2. **加字段 / 加可选 event_type = 非破坏性，不 bump**（老读者忽略，新读者用）。
3. **破坏性变更**（改字段语义、删字段、改状态机）→ bump 到 `2`。
4. 实现遇到**更高 major 版本** → **fail-closed 拒绝 + 提示升级**（不猜、不 best-effort）。
5. 同 major 内，新实现读旧 log 必须正常（旧 log 缺加法字段如 `event_id` 时按缺省处理）。

## 3. log.jsonl 事件 schema（冻结）

每个事件一行 JSON：
```jsonc
{
  "event_id": "a1b2c3…",        // v1 新增：全局唯一 opaque 串（UUIDv4 或 128-bit 随机 hex，实现选）
  "ts": "2026-06-09T10:00:00Z", // UTC ISO-8601
  "agent_id": "claude-opus",    // 座位 id（slug ^[a-z0-9][a-z0-9-]*$）
  "role": "orchestrator",       // orchestrator|worker|reviewer（由动词派生）
  "event_type": "assign",
  "task_id": "T1",              // 无关事件为 ""
  "feature": "CLI-INIT",        // 无关事件为 ""
  "payload": { }                // event_type 专属
}
```

`event_type` 枚举（v1）：`init | assign | join | checkpoint | accept | changes_requested | merge`

`role` 由动词派生（不单独信任）：`init/assign/merge→orchestrator`、`join/checkpoint→worker`、`accept/changes_requested→reviewer`。

各 event_type 的 payload 必填字段（payload 内可加未知字段）：

| event_type | payload 必填 |
|---|---|
| `init` | `project`, `seats[]`（每个 `{id, roles[], entry}`）, `protocol_version`, `base_branch` |
| `assign` | `owner`, `reviewer`, `branch`, `spec` |
| `join` | `roles[]` |
| `checkpoint` | `evidence`（字符串；多行允许，渲染时折叠为单行） |
| `accept` | `{}` |
| `changes_requested` | `reason` |
| `merge` | `{}` |

顶层字段冻结（event_id/ts/agent_id/role/event_type/task_id/feature/payload）。排序靠 `ts` + 文件追加顺序；**不引入 seq**（git 合并后跨分支行交织，单调 seq 难保证；身份靠 `event_id`）。

## 4. `.pact/` 文件契约

布局（v1 冻结）：
```
.pact/
  PROJECT.md      # 章程 + 座位表（头部含 protocol_version；座位表在受管区块）
  STATE.yml       # 派生投影（结构有文档，但 log 才权威，regenerable）
  tasks/<id>.md   # 单任务：YAML frontmatter（机器可读）+ markdown 正文（人写）
  log.jsonl       # 权威源 + 事件总线
  bin/            # 实现自带工具（pact.sh / 未来 pactify 二进制）——不入协议契约
```

JSON Schema 工件（`schemas/`）：
- `event.schema.json` — 单条 log 事件（按 event_type 分支 oneOf，各自 payload 必填项 + 顶层字段）
- `seat.schema.json` — 座位对象 `{id(slug), roles[], entry}`
- `task.schema.json` — `tasks/<id>.md` 的 frontmatter 结构
- STATE.yml **不出强制 schema**（派生）；spec 文档化其结构 + 标注 "regenerable, log 权威"

`tasks/<id>.md`（v1）：
```markdown
---
id: T1
feature: CLI-INIT
owner: opencode
reviewer: claude-opus
---
## Spec
…
## Acceptance
- [ ] …
## Handoff log
…
```
> frontmatter 是 assign 事件关键字段的**冗余镜像**，让 agent 打开单个 task 文件即可读到 owner/reviewer/feature，无需解析 log。**冲突时以 log 为权威。**

PROJECT.md 座位表放在受管区块（沿用 Phase 0 `<!-- pact:begin -->/<!-- pact:end -->` 思路），`init` 幂等重写、不覆盖人写内容。

## 5. 行为契约（冻结）

### 5.1 状态机
任务：`todo → assigned → in_progress → awaiting_review → (accepted | changes_requested → in_progress)`
feature：`planned → in_progress → awaiting_review → accepted → shipped`

### 5.2 两条铁律（the pact —— 必须强制 + validate 复查）
1. **worker 不能自标 accepted**：`owner != reviewer`（assign 时校验）；只有 `caller == task.reviewer` 能 accept/changes；且 accept/changes 要求当前态 `awaiting_review`。
2. **未全 accepted 不能 merge**：feature 下所有 task 必须 `accepted`。

### 5.3 座位身份
- `agent_id` = 项目本地、自声明、稳定的**座位**（非全局身份、非进程/session）。
- roster = `init.payload.seats` + `join` 事件；slug 规范 `^[a-z0-9][a-z0-9-]*$`；roster 内唯一。
- 职责分离靠**座位名不同**强制（非密码学认证；认证留 Team 层）。
- **task_id 全局唯一**（跨 feature）：assign 校验 + validate 复查。
- 握手：座位 id 从 vendor 入口文件（CLAUDE.md/AGENTS.md，由 init 按座位表烘焙）获得；`PACT_AGENT_ID` 未设置时 fail-closed。

### 5.4 命令动词契约（冻结名 + 必填参数语义）
```
init   --project <n> --seat "<id>:<roles>:<entry>" ...
join   <id> --roles <r1,r2>
assign <task> --feature <f> --branch <b> --owner <id> --reviewer <id> [--spec <p>]
checkpoint <task> --evidence "<text>"
accept <task>
changes <task> --reason "<text>"
merge  <feature>
status | log [--replay] | validate | help
```
> 冻结：动词名 + 必填参数语义。实现可加 `--flag`（非破坏）。bash = `pact_<verb>`，Go = `pactify <verb>`——同契约两种皮。

### 5.5 恢复语义
log 为源、STATE 为投影；任何不一致由 `log --replay` 从 log 重建。worker 崩溃 → 重 join 同座位续干。

## 6. 参考实现升 v1 + 测试

把 main 上 `pact.sh` 带到 v1（小改，保持唯一一致参考）：
- `_pact_log_append`：每条事件加 `event_id`（128-bit 随机 hex，取自 `/dev/urandom`）

- `pact_validate` 增：`protocol_version` 高于支持 major → fail-closed 拒绝；事件须含 `event_id`
- 新增 bats：event_id 存在且唯一、protocol_version 写入、高版本拒绝、未知字段被忽略（前向兼容）

`docs/specs/pact-protocol.md` 综合 §1–5 写成可独立实现的规范；`schemas/*.json` 落地。
