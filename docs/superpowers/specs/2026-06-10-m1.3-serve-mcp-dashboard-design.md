# M1.3 — `pactify serve` + dashboard + MCP server 设计

> 日期：2026-06-10 · 状态：Approved (brainstorm) · Owner：Joey
> 上游：[ROADMAP.md](../../ROADMAP.md) Phase 1 / M1.3（Pact-Base 最后一块）· [architecture.md](../../architecture.md) · 协议 v1 [pact-protocol.md](../../specs/pact-protocol.md)
> 目标：本地可观测层 —— 多项目实时 dashboard（fsnotify→SSE→React）+ stdio MCP server（让 agent 经 MCP 参与协议）。建在已有 `internal/{event,projection,pact}` 核心上，不改协议。

## 0. 目标 + 范围

M1.3 给 Pactify 加**本地可观测 + agent 接入**两个面，都复用 Go CLI 的协议核心：
- `pactify serve`：长运行 HTTP/SSE，注册表驱动**多项目** dashboard（看 N 个 .pact/ repo），observe-only。
- `pactify mcp`：stdio MCP server，每 Claude 会话一个，单项目，暴露**全动词 tools + 状态/事件 resources + 通知**。
- `pactify register/unregister`：维护 `~/.pactify/projects.json` 项目注册表。

完成后 **Pact-Base（Phase 1）齐活**。

## 1. 命令 + 包结构

**3 个新命令**（cobra，加到现有 `cmd/pactify`）：
```
pactify serve [--project <path>]...   # HTTP/SSE + 多项目 dashboard（默认监控注册表 + cwd 的 .pact/）
pactify mcp                           # stdio MCP server（cwd/PACT_DIR 单项目，座位=PACT_AGENT_ID）
pactify register <path> | unregister <path> | list   # 维护 ~/.pactify/projects.json
```

**新增包：**
```
internal/registry/   # ~/.pactify/projects.json 读写（项目路径列表 + 名字）
  registry.go
internal/serve/      # HTTP：多项目、fsnotify watch、SSE、REST、go:embed dashboard
  serve.go · watch.go · sse.go · api.go · embed.go
internal/mcp/        # stdio MCP server：tools(动词) · resources(STATE/log) · notifications
  mcp.go · tools.go · resources.go
web/                 # Vite+React+TS+Tailwind+shadcn dashboard → web/dist（入库 + go:embed）
cmd/pactify/         # cmd_serve.go · cmd_mcp.go · cmd_register.go
```

**关键架构点：**
- serve 按**项目根路径**直接解析 `<root>/.pact/log.jsonl`（不靠 `PACT_DIR` env——env 是单项目的）；mcp 用 cwd/`PACT_DIR`（单项目）。
- 两者都复用 `projection.Project` + `event.ReadAll`，**不改协议核心**；mcp 的 tools 直接调 `internal/pact` 同名动词。
- serve 与 mcp 进程模型各得其所：serve 长运行 HTTP（多项目、给人看）；mcp stdio 子进程（per Claude 会话、给 agent 用）。

## 2. pactify serve（HTTP + SSE + 多项目）

**数据流**（observe-only，单向 server→browser，用 **SSE** 不用 WS）：
```
注册表（N 个 project {id,name,path}）
  └ 每 project：fsnotify watch <root>/.pact/log.jsonl
       └ 变更 → event.ReadAll + projection.Project → push SSE 给该 project 订阅者
```

**HTTP endpoints**（给 React app；JSON）：
| endpoint | 返回 |
|---|---|
| `GET /api/projects` | `[{id, name, path, project, feature_count, awaiting_count}]`（注册表 + 每项目状态摘要）|
| `GET /api/projects/{id}/state` | `projection.State` 的 JSON（board/agents/tasks/evidence 全量快照）|
| `GET /api/projects/{id}/events` | **SSE 流**：新事件逐条 push（`event: pact`，data = 该条 event JSON）|
| `GET /` 及静态资源 | `go:embed web/dist/*` 的 dashboard |

- 一个 serve 进程监控全部项目；dashboard 切项目 = 切 `{id}`，前端订阅对应 `/events` SSE。
- `id` = 注册表里的 **name slug**（`^[a-z0-9][a-z0-9-]*$`，默认 = 路径 basename 的 slug 化，注册表内唯一；冲突则 `register` 报错要求 `--name`）。
- evidence preview / per-agent activity 都从 `state` JSON + 事件流派生（state.task 带 evidence；按 agent_id 聚合事件 = per-agent activity）。
- `serve --project <path>` 临时加项目（不写注册表）；默认含 cwd 的 `.pact/`（若存在）+ 注册表全部。
- State JSON：需要给 `projection.State` 加 JSON 标签（当前字段无 tag）或在 serve 出一个带 tag 的 DTO。**用 serve 侧 DTO**（不动 projection 的 Go 结构），把 State 映射成 `{project, agents:[{id,roles}], features:[{id,branch,status,tasks:[{id,owner,status,reviewer,spec,evidence}]}]}`。

**SSE 实现**：stdlib `net/http`，`Content-Type: text/event-stream`，每订阅者一个 channel；fsnotify 回调读取该项目新增行（记住已读 offset/行数，只推增量）→ 写入所有该项目订阅者的 channel。

## 3. Dashboard 前端（Vite + React + go:embed）

**栈**：Vite + React + TypeScript + Tailwind + shadcn/ui。（React Flow 暂不用——board/timeline 用普通组件；编排画布留 Pact-Squad。）

**内容（已锁：combined，observe-only）：**
- 顶栏：项目切换（`GET /api/projects`）+ protocol 版本 + ● live（SSE 连接态）
- 座位行：每 seat chip 显示 last action + 事件数；点击 → per-agent activity（该 agent 事件流）
- 主区：kanban board（5 列 = task 状态 assigned→in_progress→awaiting_review→accepted→shipped），卡片含 owner/reviewer；awaiting 高亮
- 右栏：选中 task → evidence preview（checkpoint 证据全文）+ 下方 live timeline
- 数据：初始 `GET /state` 快照 → 之后 `/events` SSE 增量；前端按 state + 事件维护视图
- **observe-only**：无写操作（accept/changes 按钮在 v1 不出现或灰显说明——从 UI 编排是 Pact-Squad）

**构建/嵌入：**
- 开发：`vite dev`（前端热更）代理 `/api` 到本地 `pactify serve`
- 构建：`npm ci && npm run build` → `web/dist`（**入库**，便于 `go build` 免装 Node）→ `internal/serve/embed.go` 用 `//go:embed dist` 嵌入
- `embed.go` 从 `web/dist` 嵌（用相对路径软链或把 dist 放到 `internal/serve/dist`——见实现计划，倾向把 vite `outDir` 设为 `internal/serve/dist` 以便 `//go:embed dist/*`）

## 4. pactify mcp（stdio MCP server）

**形态**：stdio JSON-RPC，每 Claude 会话一子进程，单项目（cwd/`PACT_DIR`），座位 = 会话 `PACT_AGENT_ID`。

**SDK**：官方 **`github.com/modelcontextprotocol/go-sdk/mcp`**（v1.6.1）。
```go
server := mcp.NewServer(&mcp.Implementation{Name: "pactify", Version: "v1"}, nil)
mcp.AddTool(server, &mcp.Tool{Name: "checkpoint", Description: "..."}, checkpointHandler)
// ... 其余动词
server.Run(ctx, &mcp.StdioTransport{})
```

**暴露（已锁：全动词 tools + 资源 + 通知）：**
- **tools**：`join/assign/checkpoint/accept/changes/merge/status/validate` —— 每个 handler 解析结构化 input → 调 `internal/pact` 同名函数 → 返回结果/错误。角色违规由 `pact` rules 执行时 fail-closed（同 CLI）。`PACT_AGENT_ID` 缺失 → tool 返回 fail-closed 错误。
- **resources**：`pact://state`（当前 STATE.yml 文本）、`pact://log`（log.jsonl 文本）。
- **notifications**：fsnotify watch log → 新事件时发 MCP resource-updated 通知（订阅 `pact://state`/`pact://log` 的客户端实时感知）。

**依赖姿态**（3 个新 build-time 依赖，**runtime 仍零依赖**单二进制）：
| 依赖 | 用途 |
|---|---|
| `github.com/fsnotify/fsnotify` | serve + mcp watch log |
| `github.com/modelcontextprotocol/go-sdk/mcp` v1.6.1 | mcp 协议 |
| Node 工具链（Vite/React/Tailwind/shadcn）| 仅 `web/` 构建；`web/dist` 入库，二进制 embed 静态产物，runtime 无 Node |

## 5. 测试

| 层 | 测试 |
|---|---|
| `internal/registry` | go test：projects.json 读写、add/remove、缺失文件容错 |
| `internal/serve` | go test + `httptest`：`/api/projects`、`/state`（projection DTO 正确）、`/events` SSE（写一条日志 → fsnotify → 收到 SSE event）、多项目隔离 |
| `internal/mcp` | go test：每 tool 触发对应 `internal/pact` 动词（临时 repo 验状态转换 + 铁律 fail-closed）；resources 返回 STATE/log；log 变更触发 notification。用 SDK 的内存/管道 transport 驱动 |
| `web/` | vitest：状态派生单测（board 分组、per-agent activity 聚合、evidence 取值）；`npm run build` 成功 |
| e2e | bats：`go build` → 起 `pactify serve` → curl `/api/projects` + `/state`、SSE 收一条；`pactify mcp` smoke（spawn → list tools → call status）|

**验收**：go test 全包绿；现有 76 bats + Go 测试保持绿；serve 起得来、dashboard 渲染、SSE 实时；mcp 能被 MCP 客户端 list/call 并真正改协议状态。
